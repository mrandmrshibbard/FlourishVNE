Scripting & Plugins

Write custom JavaScript logic and extend the engine with plugins.

Getting Started with Scripting

The Scripting System lets you write custom JavaScript logic that runs inside your visual novel. Scripts can manipulate variables, trigger scene jumps, play audio, show dialogue, and much more — all through a safe, sandboxed API.

  1. Open the Script Editor from the Tools menu in the header toolbar
  2. Click New Script to create a script
  3. Write your logic using the game API object
  4. Save with Ctrl+S and test with the ▶ Test Run button
  5. Use the Run Script command (Flow Control category) in your scene timeline to execute a script during gameplay
  6. Click 📖 API in the editor toolbar for a clickable reference of every game method

About Test Run: it runs against a mock game — variables start at their defaults and side-effects (dialogue, audio, navigation, runScript/callCommonEvent) are printed to the Console instead of actually happening. To see a script truly affect the game, run it from a Run Script command in Test Play.

Script Triggers

Each script has a trigger that determines when it can run:

TriggerDescription
commandRuns when a RunScript command executes in the scene timeline.
onSceneEnterRuns automatically on every scene change, as the new scene begins. These are global lifecycle hooks (not bound to one scene) — check game.currentScene inside if you only want certain scenes. Navigation calls are ignored here to avoid loops.
onSceneExitRuns automatically as you leave a scene (just before the next scene's enter hooks). Same global behavior as onSceneEnter.
globalUtility script — never runs on its own; call it from another script with game.runScript("Name").

The game API

Inside every script, a game object is available with the following methods and properties:

Variables

// Get a variable value by name or ID
let hp = game.getVariable("playerHP");

// Set a variable value
game.setVariable("playerHP", 100);
game.setVariable("playerName", "Alex");
game.setVariable("hasKey", true);

Navigation

// Jump to a different scene by name
game.jumpToScene("Chapter 2");

// Jump to a label within the current scene
game.jumpToLabel("battle_start");

Dialogue & Notifications

// Show a dialogue box (character name, text)
game.showDialogue("Narrator", "The adventure begins...");
game.showDialogue("Luna", "Watch out!");

// Show a notification toast
game.notify("Auto-saved!", "info");      // types: "info", "warning", "error", "success"

Audio

// Play a sound effect (name, optional volume 0-1)
game.playSFX("sword_clash", 0.8);

// Play background music (name, loop, optional volume)
game.playMusic("battle_theme", true, 0.5);

// Stop all music (optional fade duration in seconds)
game.stopMusic(2);

Project Info (Read-Only)

// The current scene's name and ID
let name = game.currentScene;
let sceneId = game.currentSceneId;

// A list of all scene names
let scenes = game.getScenes();
// Returns: ["Chapter 1", "Chapter 2", ...]

// All variables as a { name: value } map (current values)
let vars = game.getVariables();
// Returns: { playerHP: 100, hasKey: false, ... }  (getAllVariables is an alias)

Parameters & Calling Other Scripts

// Declare params in the Script Editor; supplied args arrive as read-only game.args
let dmg = game.args.amount;
if (game.args.crit) dmg *= 2;

// Run another script (by name or ID), optionally passing args → its game.args
game.runScript("ApplyDamage", { amount: 12, crit: true });

// Invoke a Common Event; its commands run, then execution returns here
game.callCommonEvent("ShowQuestComplete", { questId: "q_07" });

// Pause (native setTimeout is blocked — use game.wait)
await game.wait(1.5);

Inventory

If your project has Items (created by the Shop / Inventory System Wizard in the In‑Game UI editor), scripts can read/change the player's inventory. Each item is backed by a number "count" variable, so these are a no-op if no items exist yet.

let potions = game.getItemCount("Potion");   // by name or id
if (game.hasItem("Key")) game.jumpToScene("Locked Room");
game.addItem("Potion", 3);    // unique items cap at 1
game.removeItem("Potion");    // never below 0
let all = game.getItems();    // [{ id, name, count }, ...]

Characters

let chars = game.getCharacters();   // [{ id, name }, ...]

Math Utilities

let r = game.random(1, 10);      // random integer between 1 and 10
let c = game.clamp(value, 0, 100); // clamp value between min and max
let l = game.lerp(0, 100, 0.5);    // linear interpolation → 50

Logging

game.log("Debug message");          // appears in the console output
game.log("HP:", game.getVariable("playerHP"));

Examples

Damage Calculation

// Calculate damage with randomness
let attack = game.getVariable("playerAttack");
let defense = game.getVariable("enemyDefense");
let baseDamage = Math.max(1, attack - defense);
let finalDamage = baseDamage + game.random(0, 5);

game.setVariable("lastDamage", finalDamage);

let enemyHP = game.getVariable("enemyHP");
enemyHP -= finalDamage;
game.setVariable("enemyHP", enemyHP);

game.showDialogue("System", `You deal ${finalDamage} damage!`);

if (enemyHP <= 0) {
    game.notify("Enemy defeated!", "success");
    game.jumpToScene("Victory");
}

Day/Night Cycle

let hour = game.getVariable("gameHour");
hour += 1;

if (hour >= 24) {
    hour = 0;
    let day = game.getVariable("gameDay");
    game.setVariable("gameDay", day + 1);
}

game.setVariable("gameHour", hour);

if (hour >= 6 && hour < 18) {
    game.setVariable("timeOfDay", "day");
} else {
    game.setVariable("timeOfDay", "night");
}

Inventory Check

let hasKey = game.getVariable("hasKey");
let hasMap = game.getVariable("hasMap");

if (hasKey && hasMap) {
    game.jumpToScene("Secret Room");
} else if (hasKey) {
    game.showDialogue("Narrator", "You have the key, but you need a map to find the door.");
} else {
    game.showDialogue("Narrator", "The path forward is blocked.");
}

Using RunScript in Scenes

  1. In the Command Palette, open the Flow Control category
  2. Drag Run Script into your scene timeline
  3. In the Properties Inspector, select which script to run (and fill in any Arguments if the script has parameters)
  4. Toggle Wait for Completion to control whether the engine pauses until the script finishes

Security & Sandbox

Scripts run in a sandboxed environment. The following are blocked for security:

  • document, window, globalThis, self
  • fetch, XMLHttpRequest, WebSocket
  • eval, Function
  • localStorage, sessionStorage, indexedDB
  • setTimeout, setInterval, requestAnimationFrame, queueMicrotask — use await game.wait(seconds) for delays
  • .constructor access (the prototype-chain escape to Function) is rejected before the script runs

Scripts can only interact with the game through the game API object. Note: this is a practical sandbox, not a hardened security boundary — only run scripts you trust.

Validation

Click Validate in the Script Editor to check for:

  • Syntax errors — invalid JavaScript
  • Blocked API usage — references to restricted globals
  • Best practices — warnings about potentially unsafe patterns

Tips

  • Use game.log() instead of console.log() for debugging — output appears in the Script Editor console
  • Keep scripts focused — one script per gameplay mechanic
  • Test scripts with ▶ Test Run before using them in scenes
  • Disable scripts you're not using to prevent accidental execution

Common Events

Reusable command sequences — like functions for your story.

Triggers

TriggerBehavior
calledRuns only when invoked — by a Call Common Event command, a button/choice Call Common Event action, or game.callCommonEvent(). Can declare parameters.
autoRuns once at the start of every scene, before the scene's own commands. Optional condition variable gates it. Re-entering a scene after visiting another one runs it again.
parallelRuns continuously in the background alongside the scene, looping its command list. Optional condition variable turns it on/off live.

Calling a Common Event

  1. Call Common Event command in a scene timeline (pick the event + arguments).
  2. Button / choice action — choose Call Common Event and select the event.
  3. From a script — game.callCommonEvent("Event Name", { arg: value }).
  4. Nested — a Common Event can call another. Execution returns after the call.

Parameters (local scope)

A called event can declare typed parameters (string / number / boolean with defaults). Arguments are injected only for the duration of the call and the prior values are restored on return — no leakage. Arguments are coerced to the declared type; deleting a parameter cleans up dangling arguments on existing calls.

Safety limits

  • Call depth is capped (32) — exceeding it shows an error instead of freezing.
  • Cycles are detected — re-entering an event already on the call stack (A → B → A) is blocked.

Parallel events

Parallel events are for background logic. Each tick advances one command per active event, and only background-safe commands run: Set Variable, Run Script, Wait, Play/Stop Music, Play/Stop Sound Effect, Call Common Event. Presentation-takeover commands (Dialogue, Choice, Show Text/Image/Character, Set Background, Jump, Text Input, Credit Roll, screen effects, particles, tweens) are skipped. Use Wait to pace them. Parallel events are not part of save data — they resume from the loaded variable state.

Plugin / Extension System

Extend FlourishVNE with custom commands, effects, and hooks.

Getting Started with Plugins

  1. Open the Plugin Manager from the Tools menu
  2. Click the Install Plugin tab
  3. Paste your plugin source code
  4. Click Install Plugin
  5. Enable/disable plugins from the Installed tab

Plugin Structure

Every plugin must define a manifest object and a plugin variable that bundles the manifest with hook functions:

// Required: Plugin manifest
const manifest = {
    id: 'my-plugin',              // unique identifier (lowercase, hyphens)
    name: 'My Plugin',            // display name
    version: '1.0.0',             // semver version string
    description: 'What this plugin does',
    author: 'Your Name',          // optional
    category: 'utility',          // see categories below
    capabilities: [],             // reserved for future use
    dependencies: [],             // other plugin IDs this depends on
};

// Lifecycle hooks (all optional)
function onLoad(api) {
    // Called when the plugin is first loaded
}

function onEnable(api) {
    // Called when the plugin is enabled
}

function onDisable(api) {
    // Called when the plugin is disabled
}

function onBeforeCommand(api, command) {
    // Called before each command executes
    // Return modified command or undefined
}

function onAfterCommand(api, command, result) {
    // Called after each command executes
}

function onSceneChange(api, fromSceneId, toSceneId) {
    // Called when the scene changes
}

function onVariableChange(api, variableId, oldValue, newValue) {
    // Called when a variable changes
}

function onSave(api, saveData) {
    // Called before the game state is saved
    // Can modify saveData
}

function onLoadAfterSave(api, saveData) {
    // Called after a save is loaded
}

// Required: Export the plugin
const plugin = {
    manifest,
    onLoad, onEnable, onDisable,
    onBeforeCommand, onAfterCommand,
    onSceneChange, onVariableChange,
    onSave, onLoadAfterSave,
};

Hooks fire only during a play session. onBeforeCommand/onAfterCommand are observe-only in this version. Variable reads/writes via api are live during play.

Plugin Categories

CategoryDescription
commandsAdds new command types
effectsAdds custom visual/audio effects
uiModifies or extends the UI
assetsAdds asset processing pipelines
gameplayExtends gameplay mechanics
integrationReserved — the sandbox has no network access (fetch/XHR/WebSocket blocked), so external integrations aren't possible yet.
utilityGeneral-purpose utilities

Plugin API (api)

Every hook function receives an api object with these methods:

Variables

// Live during play (by name or id). In the editor, getVariable returns the
// default and setVariable is a no-op.
let hp = api.getVariable('playerHP');
api.setVariable('playerHP', 100);

Project Info

api.getProjectInfo();
// Returns: { title, version, sceneCount, characterCount }

api.getScenes();      // [{ id, name }, ...]
api.getCharacters(); // [{ id, name }, ...]

Custom Commands & Effects

Register from onLoad/onEnable. Registered commands appear in the Command Palette's 🧩 Plugins group and run your handler during play. The full type becomes <pluginId>.<type>.

api.registerCommand({
    type: 'rollDice',
    displayName: 'Roll Dice',
    category: 'RPG',
    description: 'Roll dice and store the result',
    parameters: [
        { name: 'sides', label: 'Sides', type: 'number', defaultValue: 6 },
        { name: 'target', label: 'Result Variable', type: 'variable' },
    ],
    handler: (params, api) => {
        const roll = Math.floor(Math.random() * params.sides) + 1;
        if (params.target) api.setVariable(params.target, roll);
    },
});

api.registerEffect({
    type: 'myEffect',
    displayName: 'My Effect',
    description: 'A cool effect',
    parameters: [{ name: 'intensity', label: 'Intensity', type: 'number', defaultValue: 0.5 }],
    apply: (params, api) => { /* ... */ },
    remove: (api) => { /* ... */ },
});

Parameter type: string, number, boolean, select (with options), color, variable, or asset.

Settings

Declare a settings array on the manifest to get a configuration form in the plugin's Details view. Read the values at runtime with api.getConfig().

const manifest = {
    /* …id, name, version, … */
    settings: [
        { name: 'difficulty', label: 'Difficulty', type: 'select',
          defaultValue: 'normal',
          options: [{ label: 'Easy', value: 'easy' }, { label: 'Normal', value: 'normal' }] },
        { name: 'showHints', label: 'Show hints', type: 'boolean', defaultValue: true },
    ],
};

function onRuntimeInit(api) {
    const cfg = api.getConfig();   // defaults merged with the user's choices
    if (cfg.showHints) api.notify('Hints are on');
}

Setting type: string, number, boolean, or select.

Plugin-Scoped Storage

// Persists in the PROJECT (travels with .flourish exports — not localStorage)
api.setStorage('key', value);
let value = api.getStorage('key');

Logging

api.log('Plugin message');    // prefixed with [PluginName]

Example Plugins

Auto-Save Plugin

const manifest = {
    id: 'auto-save',
    name: 'Auto Save',
    version: '1.0.0',
    description: 'Automatically saves progress at scene transitions',
    author: 'FlourishVNE',
    category: 'utility',
    capabilities: [],
};

let saveCount = 0;

function onEnable(api) {
    saveCount = api.getStorage('saveCount') || 0;
    api.log(`Auto-save enabled. ${saveCount} saves so far.`);
}

function onSceneChange(api, fromSceneId, toSceneId) {
    saveCount++;
    api.setStorage('saveCount', saveCount);
    api.log(`Auto-saving at scene change #${saveCount}`);
}

const plugin = { manifest, onEnable, onSceneChange };

Custom Dice Roll Command

const manifest = {
    id: 'dice-roller',
    name: 'Dice Roller',
    version: '1.0.0',
    description: 'Adds a dice roll command for RPG mechanics',
    category: 'commands',
    capabilities: [],
};

function onEnable(api) {
    api.registerCommand({
        type: 'rollDice',
        displayName: 'Roll Dice',
        description: 'Roll dice and store the result in a variable',
        category: 'RPG',
        parameters: [
            { name: 'sides', label: 'Sides', type: 'number', defaultValue: 6 },
            { name: 'count', label: 'Count', type: 'number', defaultValue: 1 },
            { name: 'target', label: 'Result Variable', type: 'variable' },
        ],
        handler: (params, api) => {
            let total = 0;
            for (let i = 0; i < params.count; i++) {
                total += Math.floor(Math.random() * params.sides) + 1;
            }
            if (params.target) api.setVariable(params.target, total);
        },
    });
}

const plugin = { manifest, onEnable };

Plugin Lifecycle

  1. Install — Plugin source is parsed and validated
  2. Load — onLoad() is called, plugin is in loaded state
  3. Enable — onEnable() is called, hooks become active
  4. Disable — onDisable() is called, hooks are deactivated
  5. Uninstall — Plugin is removed from the project

Plugin Details View

From the Installed tab, click Details on any plugin to see:

  • Manifest information (ID, version, author, category)
  • Registered custom commands
  • Registered custom effects
  • Plugin configuration
  • Enable/disable/uninstall controls

Tips

  • Keep plugin IDs unique and lowercase (e.g., my-cool-plugin)
  • Use api.log() for debugging — output goes to the Plugin Manager console
  • Use scoped storage (api.setStorage) instead of global state
  • Test plugins in isolation before combining multiple plugins
  • Plugins run in a sandboxed environment similar to scripts
